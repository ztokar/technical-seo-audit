What to fix, in order

Each problem was found by Google Lighthouse. Under each one is the matching guide from Google’s Modern Web Guidance, so the fix comes from the same people who run the test.

  1. 01

    SpeedCould save about 2.9 s3 outside scripts, 458 KiB

    Outside scripts slow the page down

    Lighthouse calls this: 3rd parties

    3rd party code can significantly impact load performance.

    Where it happens
    • https://www.googletagmanager.com/gtag/js?id=AW-000000000
    • https://connect.facebook.net/en_US/fbevents.js
    • https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX

    Google’s guide for the fix

    • optimize-script-priorityOptimize the loading priority of scripts so critical code runs first and non-critical code does not delay the page.
  2. 02

    SpeedCould save about 0.6 sfetchpriority=high not applied

    The main image is not loaded first

    Lighthouse calls this: LCP request discovery

    Optimize LCP by making the LCP image discoverable from the HTML immediately, and avoiding lazy-loading.

    Where it happens
    • <img alt="The Harbor Street Dental front desk" class="hero-photo">

    Google’s guide for the fix

    • optimize-image-priorityOptimize the loading priority of Largest Contentful Paint (LCP) candidate images and deprioritize non-critical images to reduce critical resource load delays.
  3. 03

    SpeedCould save about 0.5 sEst savings of 205 KiB

    Scripts load code the page never uses

    Lighthouse calls this: Reduce unused JavaScript

    Reduce unused JavaScript and defer loading scripts until they are required to decrease bytes consumed by network activity.

    Where it happens
    • https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX
    • https://connect.facebook.net/en_US/fbevents.js

    Google’s guide for the fix

    • identify-heavy-scriptsIdentify the scripts that cost the most loading and main-thread time so they can be removed, deferred or replaced.
  4. 04

    SpeedCould save about 0.3 sEst savings of 66 KiB

    Images are heavier than they need to be

    Lighthouse calls this: Improve image delivery

    Reducing the download time of images can improve the perceived load time of the page and LCP.

    Where it happens
    • /images/hero-front-desk.jpg

    Google’s guide for the fix

    • deliver-optimized-decorative-imagesDeliver optimized images in modern formats and at several pixel densities so the browser can pick the best file for the device.
  5. 05

    SpeedCould save about 0.2 s2 fonts in TTF format

    Text waits for fonts before it shows

    Lighthouse calls this: Font display

    Consider setting font-display to swap or optional to ensure text is consistently visible.

    Where it happens
    • /fonts/brand-serif-400.ttf
    • /fonts/brand-sans-400.ttf

    Google’s guide for the fix

    • visually-stable-font-fallbacksLoad web fonts without layout shift by matching the fallback font's metrics to the web font.
  6. 06

    SpeedEst savings of 118 KiB

    Returning visitors re-download the same files

    Lighthouse calls this: Use efficient cache lifetimes

    A long cache lifetime can speed up repeat visits to your page.

    Where it happens
    • https://connect.facebook.net/en_US/fbevents.js

    Google’s guide for the fix

  7. 07

    Accessibility

    Some text is hard to read against its background

    Lighthouse calls this: Background and foreground colors do not have a sufficient contrast ratio.

    Low-contrast text is difficult or impossible for many users to read.

    Where it happens
    • <p class="insurance-note">

    Google’s guide for the fix

    • contrast-colorPick a text color that stays readable against any background color.

How this was measured

Both tools are fetched fresh on every run, so this audit follows Google’s own updates. A lab test is one visit on one connection. It does not replace Search Console or real-visitor data.
